# CSS layout features for a native UI engine

The target is the geometry needed to build and edit application screens. A Rust declaration and published layout are one deliverable. Lowering a CSS spelling, including its defaults, to those declarations is a second deliverable. The pinned harness tests particular combinations of inputs and records both outcomes independently. [Implementation goal](implementation-goal.md) · [Fixture ledger](current-cases.tsv)

| Feature family | Geometry applications should be able to request | Current implementation and remaining work |
| --- | --- | --- |
| Box generation and flow | An ordinary in-flow box, a hidden subtree, a child outside flow, block, flex and grid formatting contexts, and independent formatting boundaries | Native child modes, disabled subtrees, free placement and owned flex/grid rules cover these foundations. CSS inline outer display, anonymous boxes and box flattening such as `display: contents` need distinct tree semantics. |
| Box model and sizes | Content and border box sizing, physical and logical padding, borders, positive/negative and automatic margins, preferred/minimum/maximum sizes and aspect ratio | The solver uses outer sizes and padding. The adapter converts border/content box declarations. The host supplies border paint. Pixel, parent-fraction, fill, intrinsic and ratio dimensions are native. Box edges expressed using percentage or mixed units need a containing-block reference throughout measurement. |
| Intrinsic sizing | Min-content, max-content, fit to available space, intrinsic or replaced content, height-for-width and width-for-height | Text and custom measurement callbacks provide intrinsic inputs. Tracks expose minimum and preferred extents. Measure again at the assigned width when wrapping changes the block size. CSS value grammar and measured contents can be expanded independently. |
| Block formatting | Fill the inline axis, size the block axis to content, align with auto margins, collapse signed adjoining block margins, preserve formatting boundaries | Native block flow and vertical block projection handle these operations. Empty grids and flexible formatting contexts isolate through-collapse. Document flows involving inline runs, floats or clearance require additional formatting machinery. |
| Writing modes | Horizontal and vertical block progression, LTR/RTL, inline/block sizes, min/max, edge mapping and nested overrides | The owned tree resolves inherited writing contexts into physical axes. The text host owns glyph shaping and bidirectional text. Per-mode coverage for alignments and imported CSS shorthands should grow with their implementations. |
| Flexible layout | Row/column, reversed axes, growth, basis-scaled shrink, bound freezing, order, wrapping and wrap-reverse, main/cross-axis gaps, item and line alignment | Managed flex exposes these declarations. Ordinary stacks retain their fixed-size behavior. The CSS adapter handles a subset of flex inputs, including shrinkable lines embedded in grid scenes. Multi-line and basis combinations require additional fixture coverage. |
| Track sizing | Explicit and implicit rows and columns, fixed/percentage/intrinsic sizes, fractional weights, `minmax`, `fit-content`, content stretching and distinct gutters | TrackGrid provides native heterogeneous tracks, collapse-aware gaps, fractional allocation, content maxima and optional content floors. The adapter represents a subset of intrinsic keywords and sizing functions. More min/max combinations and cyclic percentage cases need direct coverage. |
| Grid placement | Numeric and named lines, spans, rectangular named areas, sparse/dense flow in either direction, explicit and implicit grids, fixed repeat, auto-fill, auto-fit and shared subgrid tracks | Native placement covers numeric starts, spans, single-track automatic repeat and subgrid axes. The harness translates many numeric lines including negative lines within an explicit template. Named lines and areas, placement before the explicit origin, cycling implicit track patterns, compound auto-repeat and positioned grid areas remain extensions. |
| Box alignment | Start/end, self-start/self-end, stretch, center, space-between/around/evenly, safe overflow, auto margins, first and last baselines | Native track and flexible layouts share spacing arithmetic and support baseline inputs. The public choices vary by context. Safety, baseline synthesis and imported alignment keywords need separate verification for each writing mode. |
| Positioned layout | Absolute and fixed boxes against the right containing block, inset sizing, alignment of out-of-flow children, sticky constraints, and a popup anchored to another box with a fallback side | Managed rules expose explicit references and visual geometry. CSS containing-block discovery, static positions, and each grid-area/inset combination need adapter coverage. |
| Overflow and scrolling | Per-axis overflow, clips, content extent, scroll range and offset, stable gutters and nested scrollports | The owned tree publishes these quantities for drawing and hit testing. Platform input, scroll animation and painting belong to the host. Imported overflow keywords also affect item automatic minimums. |
| Containment and responsiveness | Size or inline-size isolation, placeholder intrinsic sizes, container names and breakpoints on the allocated size | Owned container queries can alter child arrangements as panels resize. Additional CSS query syntax, container units and containment effects should be added when their reference size and invalidation behavior are defined. |
| Units and calculations | Fixed logical pixels, percentages, factors, host font/viewport units, sums of lengths and percentages, `min()`, `max()`, `clamp()` | Native contributions, bounds and positioned lengths cover common cases. A CSS-facing layer can resolve absolute, font and viewport units from host metrics. Expressions that depend on an unresolved axis must retain that dependency until solve time. |
| Publication | Fractional geometry, stable shared edges under device snapping, measured baselines, actual tracks, and identical results after edits or fresh solves | The owned tree publishes rectangles and unrounded track edges. Tests exercise physical RTL edges, shared tracks, retained updates, rejected Batch frames and retries. |

A richer document renderer would also need inline line-box construction, floats and clearance, table layout, multicolumn flow and page/column fragmentation. Those are distinct product features with their own acceptance scenes. Paint, compositing, stacking, selectors, cascade and CSS parsing belong to neighboring layers, which can supply resolved declarations and consume the resulting geometry.

Grid acceptance uses an authored asset sheet with both automatic placement and an equivalent explicit version, and a separate fixture runner that compares native published tracks to recorded browser values.
