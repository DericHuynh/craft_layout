# Layouts that change at an edge

Three independent component authors predicted rectangles before solving, then varied the input on a retained tree. The grid minimum also received a second author's vertical-axis trial. We used native Rust, literal CSS through the fixture importer, and DOM measurements from Chrome for Testing 158.0.8127.88. Selected cases were also measured in the older Qt WebEngine build using Chromium 83.0.4103.122.

## Corrections

| Case | Original result | Corrected result and control |
| --- | --- | --- |
| Hard repeated grid track with a leading status rail | In a 116px panel, showing a 36px implicit rail and an 8px gap reduced a card with a 100px minimum to 72px. The internal representation of the prepended track lost the repetition's floor. | The card occupies x=44..144 and overflows by 28px. At a panel width of 160 it uses 116px. Hiding the rail in the original panel restores the full 116px. Both auto-fit and auto-fill preserve the minimum. Chrome gave the same result for the equivalent CSS. |
| Sticky title in a padded article section | At scroll offset 80 the 16px title remained at y=2 and crossed the section's 12px bottom padding. Completely clamping the final position also pulled an already overflowing title backwards, even before any scroll. | With a 2px top inset the title starts at y=28, reaches y=2 at offset 40, and leaves at y=−8 at offset 80. A 4px bottom margin moves the last result to −12. An oversized title whose normal top is 32 stays at 32 before scrolling. Both Chromium versions agreed. |
| Absolutely positioned badge with opposing physical insets | An RTL positioned panel with an LTR static wrapper placed a 40px badge at x=10. The opposite combination placed it at x=136. | In a 200px panel with left=10 and right=24, RTL puts the badge at 136 and LTR at 10. The positioned ancestor decides. Making the wrapper positioned transfers that choice to the wrapper. All six block/grid variants matched both Chromium versions. |
| Logical margin longhands in literal CSS | The native logical-margin API worked, but the importer rejected `margin-inline-start: auto`. | All four inline/block start/end longhands use the item's own writing context. Physical and logical declarations targeting the same edge use their order in the source XML. The controls exercise auto, 10%, negative and zero margins, an orthogonal child, and both orders. Chrome 158 matched all 14 boxes in this fixture. |

The first two corrections change native geometry. The latter two change CSS fixture translation. The existing source corpus retains its original browser and native expectations. [Grid placement](https://www.w3.org/TR/css-grid-2/#placement) · [Sticky movement limits](https://www.w3.org/TR/css-position-3/#stickypos-insets) · [Overconstrained horizontal positioning](https://www.w3.org/TR/CSS22/visudet.html#abs-non-replaced-width) · [Logical property groups](https://www.w3.org/TR/css-logical-1/#logical-property-group)

## Where a workaround changes the request

| Component | Direct declaration and observed geometry | Consequence of the alternative |
| --- | --- | --- |
| Catalog, 184px wide, 40px cards | Shared grid columns at x=0,48,96,144 put the sixth card at x=48. Eight cards make a 46px-high shelf. | Flex with space-between puts the sixth card at 144. One invisible 40px card moves it to 72. That spacer happens to align seven real cards, but with eight it creates a third line and a 52px shelf. Chrome 158 reproduced all three shelf heights. [Last-row spacer recipe](https://travishorn.com/some-ways-to-align-the-last-row-in-a-flexbox-grid/) |
| Pills measuring 25, 31 and 26px | Two 6px gaps give an exact wrap threshold of 94px. At 93px the last pill starts the next line. | A 6px leading margin on each pill needs 100px and indents the first pill by 6px. A compensating outer margin plus an expanded container recovers the child positions. [Flex gap recipe](https://coryrylan.com/blog/css-gap-space-with-flexbox) |
| Wrapped toolbar with trailing 20px action | A managed flex auto margin puts the action at x=86 in a 106px toolbar, then x=79 on its own line in a 99px toolbar. | Simple `ChildrenLayout::Wrap` treats the automatic margin as zero and gives x=80 and x=0. The `Margin::AUTO` documentation now points authors to `NodeRules::flex` for per-line free-space distribution. [Flex auto margins](https://www.w3.org/TR/css-flexbox-1/#auto-margins) |
| RTL toolbar | In 144px, the logical leading auto margin puts the action at x=12..34. Six native writing-mode/direction combinations matched fresh trees. | A physical left auto margin gives x=78..100. Reversing the row by hand gives x=48..70. A horizontal LTR editor inside a vertical RTL strip uses its own axes. Chrome 158 agreed with Craft's x=15..37 for the editor. Chromium 83 placed it 8px farther left. [RTL authoring examples](https://rtlstyling.com/posts/rtl-styling/) |
| Full-width grid banner or badge | With one card in a 320px auto-fit grid, an in-flow banner spanning the grid keeps three 100px columns occupied. | The same span on an absolutely positioned overlay leaves two tracks collapsed. The card expands to 320px and the overlay still covers all 320px. Both Chromium versions agreed. [Auto-fit and empty tracks](https://www.w3.org/TR/css-grid-2/#auto-repeat) |
| Tiny overflow in a data pane | For a 100×100 pane with 10px vertical and 8px horizontal classic scrollbars, 100×101 content activates both. The scrollport becomes 90×92 with maximum offset (10,9). Shrinking the content to 97×99 restores both dimensions to 100. | Overlay bars leave the port at 100×100. On an 80×80 document, reserving both configured native gutters leaves 90×92. In horizontal writing, CSS `scrollbar-gutter: stable` gave Chrome 158 a 90×100 port. [CSS scrollbar gutter](https://www.w3.org/TR/css-overflow-3/#scrollbar-gutter-property) |
| Sticky title that belongs to a single grid row | At scroll offset 80 a 16px title inside a section filling the first 60px row has top −16 and bottom 0. | A title placed directly in the two-row grid is still at y=2. Craft and both Chromium versions give the direct grid item whole-grid scope in this case. The section expresses exactly where the title should leave. The Grid spec identifies the grid area as the item’s containing block. The whole-grid result here records the measured behavior and Craft’s documented parent boundary. [Grid areas](https://www.w3.org/TR/css-grid-2/#grid-area-concept) · [Sticky positioning](https://www.w3.org/TR/css-position-3/#stickypos-insets) |

Two further checks qualify those results. In the grid minimum's vertical trial a 140px panel held two implicit 8px rows, two fractional rows with 60px floors, and three 5px gaps. The second ticket ended at y=151 as predicted. Removing one ticket gave the other 114px with auto-fit and 60px with auto-fill. Reinstating both tickets and both implicit rows restored their original rectangles.

For the padded reader, `overflow: clip` preserved the outer scrollport as the sticky reference. Craft and Chrome 158 both reported y=2 at offset 40. Making the section `overflow: hidden` made the title travel with the section. There is a remaining 2px difference in the hidden case. With 8px leading padding, Craft gives y=28 initially and −12 at offset 40. Chrome 83 and 158 give y=30 and −10. This difference is separate from the corrected trailing padding and margin limits. [Clip and hidden in a sticky layout](https://benfrain.com/yes-you-can-use-position-sticky-and-overflow-together/)

A mirrored sticky footer with a 2px bottom inset and a 4px top margin provided a check in the other direction. At scroll offsets 0, 20, 50, 70 and 0, its top was 56, 42, 42, 26 and 56 in both Craft and Chrome 158.

## Reproduce

```sh
cargo test --locked --test edge_grid --test edge_scroll --test edge_logical --test edge_wrap
cargo test --locked --test conformance -- --workarounds
python benchmarks/conformance/compare_workaround_browser.py --browser /path/to/chrome-headless-shell --pattern 'edge_*.xml'
```

The optional Python command uses Playwright and a real Chromium executable. It builds the DOM from the XML inputs and compares each parent-relative rectangle with the checked-in Craft result. It reports versioned differences and exits with status 1 if it finds any. At 158.0.8127.88 all 42 boxes across the five new XML trees matched. Omitting the pattern compares the entire directory. Across all 20 local fixtures the two differences were again the [previously measured padded cards and nested flex scroller](css-workarounds.md). Scroll offsets, grid track lists and native diagnostics have their own Rust checks. The pinned 6,604-case corpus runs separately with `cargo test --locked --test conformance -- --require-resolved`.
