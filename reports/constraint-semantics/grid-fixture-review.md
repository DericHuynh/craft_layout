# Reviewing the first Grid mismatches

The first run that compared CSS Grid track lists as well as node rectangles found 468 mismatches across 117 fixture families. The family ledger records the authored constraint, a concrete observation from that run, and the revised outcome of each variant. **All 468 now match their archived browser expectations for rectangles and published track lists.** Each family has four XML files crossing LTR and RTL with content-box and border-box sizing. Coordinates are parent-local. Track lists give lengths in CSS pixels in source order. The numeric example in each row uses border-box LTR. [Family ledger](grid-mismatch-families.tsv) · [Pinned source XML](https://github.com/DioxusLabs/taffy/tree/4e59968eda29ceeb0bbaeb3993c8cd38baa3d0a6/tests/xml)

## Where the first results went wrong

| Initial cause | Families | Judgment from the authored constraints |
| --- | ---: | --- |
| CSS flex sizing | 46 | A fixed preference inside a CSS flex row can shrink. In 45 families the track lengths and grid items already matched. The nested child alone kept its full 100px. Bevy's nested grid adds two 5px margins to the same issue. |
| Flexible span minimum | 22 | A single unbreakable contribution can set a floor on one or more qualifying flexible tracks. A 100px item across 1fr and 3fr needs a 25/75 allocation. A fixed zero minimum changes which tracks can grow. |
| Track and flex sizing | 12 | Two fixes are independent. Allocate the automatic and flexible tracks, then let their child shrink to the spanned width. Correcting one can leave the other visibly wrong. |
| Intrinsic fractions | 9 | For a 60px card spanning 1fr and 2fr, a 20px fraction handles both tracks and makes the width 60px. The original 30px fraction gave the entire grid 90px. Zero and fractional factors exercise additional sizing policies. |
| Content floor | 6 | Hard content minima can exceed a cap or container. A word 40px wide needs a 40px track even with fit-content(30px). A word 80px wide across two auto columns and an independently required 60px column need 140px inside a 100px grid. |
| Overlapping span minima | 5 | Multiple items constrain the same tracks. Giving 60px to an initial pair and 150px to a subsequent triple should not charge their intersection twice. For four equal weights, the checked result is 30/50/50/50. |
| Nested grid measurement | 5 | A grid supplies a natural size to its enclosing flex container. Even a single explicitly declared empty 20px row supplies positive height. Two columns of 20px text supply a natural width of 40px. |
| Intrinsic maximum | 4 | When a grid is measured at max-content, a finite track maximum can establish a nonzero size, even with an unresolved percentage minimum. The empty middle minmax(20px, 40px) track gets 40px. |
| Viewport translation | 3 | A finite available size bounds fit-content, while a max-content measurement has no finite percentage basis. Treating either as an unconditional width produced 400px for two 80px columns, or one million pixels for a 40px square. |
| Span distribution | 2 | A track whose own content already fits can keep that width while a neighboring track absorbs a wider span. A 70px text run over a 5px gap and a fitted 20px neighbor leaves 45px for the other track. |
| Formatting context | 1 | An empty Grid container separates two groups of adjacent block margins. Counting both 10px gaps gives a 40px parent instead of 30px. |
| Cross-axis measurement | 1 | One item establishes a 100px row. A square in that row needs a 100px column. In a 150px grid that leaves 50px for its neighbor's text, which wraps to 20px high. |
| Item measurement | 1 | A start-aligned text box in an established 40px cell can wrap from 80 × 10px to 40 × 20px. Changing the already-correct tracks would move the other items. |
| **Total** | **117** | **All 468 match the archived browser on the revised run.** |

The 70 families named `grid_flex_track_intrinsic_sizes_003` show why checking both layers matters. In 45 families only the grandchild's width differs. Another 13 have a track-sizing discrepancy with the grandchild already at the correct width. Twelve combine both symptoms. Under RTL, a correct-width grandchild can also move when the containing track has the wrong size. The groups named `automin`, `fixedmin` and `mincontentmin` supply, respectively, an omitted item minimum, a 50px minimum and a **100px pixel minimum**. The last group does not declare the CSS keyword `min-content`. ## Which answers an author could predict

**A clear defect can reproduce without any CSS.** A 60px span on an intrinsically sized 1-to-2 weighted pair has an independent solution of 20px and 40px. Adding an unoccupied third track weighted 3 extends the width to 120px. The original solver produced widths of 90px and 180px. Likewise, a fixed 20px grid row inside a content-sized parent should register a positive height. These expectations follow from a weighted allocation or an explicit dimension. They can be tested through the public engine even if the fixture translation changes. [Native track regressions](../../tests/track_layout.rs)

**A translation error can look identical to a track error on screen.** One fixture supplies 54px of inner space to minmax(0px, 0.5fr). Both engines recorded a 27px track and a 27px grid item. The first comparison still failed because a 100px grandchild inside the fixture's implicit flex row stayed 100px wide. In CSS the row applies default shrink to a preferred width. Craft's fixed pixel declaration and its flexible-item sizing rule express separate requests. Preserving that distinction lets a component author choose a fixed-size icon or a shrinking panel. [Flexbox initial values](https://www.w3.org/TR/css-flexbox-1/#flex-initial) · [Fixture translation](../../tests/conformance/translate.rs)

**Some valid constraint systems admit more than one geometric solution.** In `grid_taffy_issue_624`, a 100px card occupies column one and a 120px card spans columns one and two. Both a 100/20 split and a 110/10 split can contain them. Preserving the first column's established preferred size gives 100/20 and keeps its following neighbor stable. That is a reason for choosing an allocation rule. The declarations alone do not establish which movement every application designer would prefer. A square with a definite 100px height supplies an independent width of 100px. Its cross-axis dependency has a finite geometric answer.

**Native fractions and CSS fractions have different declared minima.** Craft's bare `Track::Fr` starts at zero. A component that needs an unbreakable label to force overflow can select `TrackMin::Content` explicitly. Bare CSS `1fr` carries an automatic minimum, so the translator supplies the corresponding native minimum. An explicit CSS `minmax(0, 1fr)` requests the zero floor. A subtler case uses a 0fr CSS row with a 100px automatic floor and an empty 1fr row in an intrinsically sized grid. CSS lets that first row establish the common fraction and the fixture publishes two 100px rows. A zero-minimum native track is a distinct author choice. [Native track definitions](../../src/tracks.rs) · [CSS track syntax](https://www.w3.org/TR/css-grid-1/#track-sizing) · [Sizing flexible tracks](https://www.w3.org/TR/css-grid-1/#algo-flex-tracks)

**The pinned browser also differs from published CSS guidance.** Two families give a 60px spanning card weights of 0.2 and 0.3. The archive assigns 24px and 36px, preserving the 2-to-3 ratio for the entire hard floor. The March 2025 CSS Grid Level 1 text says to allocate only the fraction-factor sum proportionally, then split the remaining floor equally. Applying that step to this 60px contribution allocates 12px and 18px first, then 15px apiece, giving 27px and 33px. This interpolation makes the result tend continuously toward equal shares as both factors approach zero. The public native regression chooses a proportional hard floor, distinct from the rule for sharing *remaining* definite space. The archived score therefore gives limited evidence about CSS specification conformance for this case. [Spanning flexible tracks](https://www.w3.org/TR/2025/CRD-css-grid-1-20250326/#algo-spanning-flex-items) · [Fixture with two tracks](https://github.com/DioxusLabs/taffy/blob/4e59968eda29ceeb0bbaeb3993c8cd38baa3d0a6/tests/xml/grid/grid_fr_span_2_proportion_sub_1_sum__border_box_ltr.xml)

## What the author trial adds

The asset browser's predictions preceded its first solve. With a 92px thumbnail minimum and three 8px gaps, four columns fit at 392px. Reducing the available width to 391px moved the logo to a fourth row. Filtering down to a cover spanning two columns and one icon on a 502px sheet produced 162px tracks with auto-fit and 94px tracks with auto-fill. The overlay consumed zero tracks, including when the filter hid all eight cards. The geometry passed on the preceding revision as well as the new one. The new track-list API additionally exposes collapsed tracks to the editor's column guides. [Predictions and observations](../../examples/asset_browser/README.md)

The paired alternative explicitly assigned every visible card a row and column in the same eight states. It matched all 40 component rectangles or hidden states and required 44 address assignments. The automatic version needed the two wide spans and no corrective placement edit. In a second trial, two late pinned items reserved their cells before an earlier automatic cover. A tag moved from slot four in sparse flow to the hole in slot zero in dense flow, in both orientations. A product requirement to preserve reading order or fill gaps selects between these two outcomes. [Executable trials](../../examples/asset_browser/main.rs)

The explicit address assignments in this sample supply evidence about the cost of a workaround because the author tried both declarations against the same prediction. The source XML records final declarations only. A zero minimum, a cap or a pinned span in a fixture gives no evidence about the original author's motive. No input in this set demonstrates memory unsafety. The scope of the comparisons is geometric agreement, including separate row and column lists where the XML supplies them.
