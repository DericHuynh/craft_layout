# Layout verification

Keru compares a retained view after an edit with a fresh full build of the same tree. The observable result is the sequence of visible node incarnations in document order and the eight `f32` bit patterns in each node's absolute and parent-local rectangle. A frame may skip writes and leave detached nodes in the host's backing storage. The history proofs compare the two visible sequences and establish the cache invariant needed by the next frame. [Acyclic edit history](history.rs) · [Cyclic replay history](replay_history.rs) · [Retained output history](replay_publication.rs) · [Tree order](traversal.rs)

## Verify a downstream measurer

Implement `Measurer<N, C>` in the same Rust source your adapter calls. `N` is the node ID and `C` holds the immutable measurement inputs, such as text and font metrics. In the Verus build, implement `Model<N, C>` with a pure `expected(node, content, request)` function and a validity predicate for the private cache. Verify that constructors establish the predicate. From a valid cache, measurement must preserve it and return the exact words given by `expected` without unwinding. A cache-free implementation can use `true` as its predicate. [Public contract](../src/measurement.rs)

Use `Request::TextWidth` for unwrapped text width, `Request::text_height` for wrapped or unwrapped text height, and `Request::from(input)` for custom content. In a verified cache, use `Request::same_input` to compare the full request, including axis, optional constraints, signed zeros and NaN payloads. Call `SizeBits::to_size()` to convert the result back for `TreeAdapter`. These Rust boundary conversions are covered by native tests. The Verus contract operates on the bit words. Your adapter must forward its callbacks to the verified routine, supply the corresponding node and content, and report content changes to Keru. [Native adapter tests](../tests/adapter.rs)

The downstream example uses `keru_layout::measurement` in an ordinary Cargo build and imports the Verus contract from the same source when checking the measurer. Export the contract with the same Verus release you use for the downstream proof. Run these commands from a Keru checkout. Substitute your measurer's source file for the example to check your implementation. [Downstream example](../examples/verified_measurement.rs)

```sh
mkdir -p target/verus-measurement
RUSTUP_TOOLCHAIN=1.99.1 verus --no-cheating --compile --crate-type lib --crate-name keru_measurement \
    --out-dir target/verus-measurement \
    --export target/verus-measurement/keru_measurement.vir src/measurement.rs
RUSTUP_TOOLCHAIN=1.99.1 verus --no-cheating --crate-type lib \
    --import keru_measurement=target/verus-measurement/keru_measurement.vir \
    --extern keru_measurement=target/verus-measurement/libkeru_measurement.rlib \
    examples/verified_measurement.rs
cargo run --example verified_measurement
```

## Pixel unscaling by a reciprocal

For positive finite binary32 scale $s$ and a nonnegative finite binary32 edge $x$, the product $t=xs$ is exact in binary64. It has at most 48 significant bits. Let $q$ be $t$ rounded to the nearest integer with ties away from zero, and let $u=q/s$ be the exact unscaled value. For $q>0$, the reciprocal and the unscaled intermediate values are within the normal binary64 range. The original binary64 division differs from $u$ by at most $2^{-53}u$. The binary64 reciprocal followed by binary64 multiplication differs by at most $(2^{-52}+2^{-106})u$, which is less than $2^{-51}u$.

If $q=t$, then $u=x$. A nonzero binary32 value is at least $2^{-25}u$ away from any binary32 rounding midpoint. Otherwise the nonintegral product has $t<2^{47}$, so $q\leq 2^{47}$. Write $s=m2^k$ and a binary32 midpoint $h=p2^e$ using odd positive integers $m<2^{24}$ and $p<2^{25}$. This representation also covers the subnormal midpoints and the overflow threshold. Any finite binary32 value $x$ is at least $2^e$ away from $h$.

If $k+e\geq 0$, then $sh$ is an integer. Equality $q=sh$ would imply $|t-q|=s|x-h|\geq 1$, contradicting $|t-q|\leq 1/2$. The nonzero integer gap gives $|u-h|/u=|q-sh|/q\geq 2^{-47}$.

If $k+e<0$, write $sh=mp/D$, where $D=2^{-(k+e)}$ is even. Then $qD-mp$ is a nonzero integer. A midpoint that could lie between the two binary64 approximations must satisfy $h\geq u/2$, so $qD\leq 2mp<2^{50}$. Hence $|u-h|/u=|qD-mp|/(qD)>2^{-50}$.

In each case the two binary64 approximations stay on the same side of every binary32 midpoint and produce identical published words. Negating the edge preserves the argument. Zero results and infinities keep their signs under both unscaling operations, and NaNs remain NaNs. The arithmetic checker verifies how the kernels compute and use the reciprocal. [Arithmetic checker](pixel_rounding.py)

## Fusing the half-pixel bias

The nonzero finite product of a binary32 edge and scale has at most 48 significant bits and fits in the normal binary64 exponent range. Its binary64 multiplication is exact. A positive scale preserves the edge's sign, including signed zeros and infinities, so the FMA kernel takes the bias sign from the original edge. The binary64 FMA and the separate binary64 multiply and add round the same exact biased value. Both then truncate and unscale identically. NaNs remain NaNs. Fusing in binary32 can move a value across a half-pixel boundary. [Arithmetic checker](pixel_rounding.py)

## Packed power-of-two scales

For $s=2^k$ with $-126\leq k\leq 126$, the scale and its inverse are both exact normal binary32 values. A finite scaled edge retains at most 24 significant bits. If its magnitude is at least $2^{23}$, it is already integral and snapping returns the original edge, including when the binary32 multiply overflows. The binary32 comparison cannot misclassify a finite scaled edge near $2^{23}$ because scaling is exact there. Below the cutoff, the product is exact whenever it is normal. Smaller products may round to a subnormal or signed zero, and either value snaps to the same signed pixel zero. The rounded integer fits exactly in binary32. Its product with the exact binary32 reciprocal is exact in binary64, so a binary32 multiply publishes the same once-rounded value as the generic path. The original lane preserves infinities and NaN classification when the comparison fails. [Packed kernel](../src/pixel_grid/vector.rs)

## Scope of the equivalence result

The frame composition theorem compares the visible host view after a successful sizing route with the complete output stream of an independent full solve. It covers the ranked queue, retained tape, structural regions, and root replay in the model. It uses the actual selected placement recipes and replays their write events onto the previous host view. A skipped write keeps its previous value only when its local declarations, producer words, and inherited frame agree. [Frame composition](frame_equivalence.rs) · [Publication replay](replay_publication.rs)

The acyclic reference follows the full solver's ordered depth-first requests. A pending finish can only have ancestors of higher rank, so each of its reads is already solved. A fresh depth-first run therefore agrees with the ranked result even when their execution orders differ. The production walk exposes the actual request stream in live preorder and distinguishes prepared Finals, Wrap Fill shortcut writes, and DFS requests. For the viewport shortcut, both packed root axes satisfy the ordinary Regular and Final equations. The viewport resize with independent fixed children and the registered fixed-pixel edit give concrete sizing compositions. The paired scalar producer proof covers every declared Fill and Frac case under matching physical inputs. The native Wrap Flow proof binds line boundaries, cross metrics, and the packed extent to the ordered child inputs. Other prepared slots must satisfy their own producer equations before reuse. Cyclic regions use ordered replay so that provisional reads keep their original order and words. [Full sizing walk](../src/sizing_pass.rs) · [Scalar producers](../src/sizing_finish.rs) · [Wrap Flow](../src/sizing_finish/flow.rs) · [Viewport and frame composition](frame_equivalence.rs) · [Acyclic full reference](ranked_full.rs) · [Cyclic replay](replay_view.rs)

The verified frame driver distinguishes selecting a sizing path, completing its work, and publishing a view. A successful ordinary frame calls full or retained placement exactly once according to the plan and adapter retention contract. Retained placement requires the same viewport and an unchanged scale flag, with placement marks from structural planning or numeric sizing. Both this call and the engine's full solve carry a proof-only snapshot of the actual placement entry's ordered writes and resulting rectangles. A rejected ordinary frame calls the adapter's full solve. Each checked frame calls the engine's canonical full solve, and checked success depends on both complete comparisons. [Frame driver](../src/incremental/publication.rs) · [Placement entry](../src/placement_entry.rs) · [Checked sizing and view](../src/view_check.rs)

The native placement adapter reads both Final slots from the node's packed record. It clears a placement mark without changing any sizing values or other records. The same sink preserves axis order and writes both rectangles to the host. Before the callback, the verified writer maps every NaN edge to `0x7fc00000`, so an arithmetic NaN payload cannot distinguish the emitted views. Other words, including the two signed zeros and infinities, pass through unchanged. Computed inner measurement constraints select positive zero for either zero sign or an unordered subtraction. The regression exercises a successful incremental replay whose NaN payload used to differ from the full result. [Placement writer](../src/placement_node.rs) · [Placement adapter](../src/placement_adapter.rs) · [Word proof](../src/input_words.rs) · [Regression](../tests/owned_api.rs)
