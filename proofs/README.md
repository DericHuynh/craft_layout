# Layout verification

Keru compares a retained view after an edit with a fresh full build of the same tree. The observable result is the sequence of visible node incarnations in document order and the eight `f32` bit patterns in each node's absolute and parent-local rectangle. A frame may skip writes and leave detached nodes in the host's backing storage. The history proofs compare the two visible sequences and establish the cache invariant needed by the next frame. [Acyclic edit history](history.rs) · [Cyclic replay history](replay_history.rs) · [Retained output history](replay_publication.rs) · [Tree order](traversal.rs)

## Reproduce

Run from the repository root with the Verus release and its bundled Z3 on `PATH`. The floating-point checks compile the production Rust arithmetic and check the resulting LLVM instructions. Pixel snapping uses the x86-64 Linux target. The verifier used here is Verus `0.2026.11.02.8bf68ee` with Rust `1.99.1`. The native declaration and registration checks use Kani 0.68.0 and CBMC 6.11 with the nightly Rust shown below. Cargo builds use the crate's normal stable toolchain. [Verus release](https://github.com/verus-lang/verus/releases/tag/release%2F0.2026.11.02.8bf68ee)

```sh
RUSTUP_TOOLCHAIN=1.99.1 verus --no-cheating --crate-type lib proofs/view.rs
RUSTUP_TOOLCHAIN=1.99.1 python3 proofs/pixel_rounding.py --z3 "$(dirname "$(command -v verus)")/z3"
RUSTUP_TOOLCHAIN=1.99.1 python3 proofs/fill_budget.py --z3 "$(dirname "$(command -v verus)")/z3"
RUSTUP_TOOLCHAIN=nightly-2026-08-21 python3 proofs/same_input.py
RUSTUP_TOOLCHAIN=nightly-2026-08-21 kani proofs/block_flow_native.rs
RUSTUP_TOOLCHAIN=nightly-2026-08-21 kani --no-overflow-checks -Z unstable-options proofs/stack_line_native.rs --cbmc-args --fpa
cargo test --locked
cargo test --locked --no-default-features
```

## Verify a downstream measurer

Implement `Measurer<N, C>` in the same Rust source your adapter calls. `N` is the node ID and `C` holds the immutable measurement inputs, such as text and font metrics. In the Verus build, implement `Model<N, C>` with a pure `expected(node, content, request)` function and a validity predicate for the private cache. Verify that constructors establish the predicate. From a valid cache, measurement must preserve it and return the exact words given by `expected` without unwinding. A cache-free implementation can use `true` as its predicate. [Public contract](../src/measurement.rs)

Use `Request::TextWidth` for unwrapped text width, `Request::text_height` for wrapped or unwrapped text height, and `Request::from(input)` for custom content. In a verified cache, use `Request::same_input` to compare the full request, including axis, optional constraints, signed zeros and NaN payloads. Call `SizeBits::to_size()` to convert the result back for `TreeAdapter`. These Rust boundary conversions are covered by native tests. The Verus contract operates on the bit words. Your adapter must forward its callbacks to the verified routine, supply the corresponding node and content, and report content changes to Keru. [Native adapter tests](../tests/adapter.rs)

The downstream example uses `keru_layout::measurement` in an ordinary Cargo build and imports the Verus contract from the same source when checking the measurer. Export the contract with the same Verus release you use for the downstream proof. Run these commands from a Keru checkout. Substitute your measurer's source file for the example to check your implementation. [Downstream example](../examples/verified_measurement.rs)

```sh
mkdir -p target/verus-measurement
RUSTUP_TOOLCHAIN=1.99.1 verus --no-cheating --compile --crate-type lib --crate-name keru_measurement \
    --out-dir target/verus-measurement \
    --export target/verus-measurement/keru_measurement.vir src/measurement.rs
RUSTUP_TOOLCHAIN=1.99.1 verus --no-cheating --crate-type lib \
    --import keru_measurement=target/verus-measurement/keru_measurement.vir \
    --extern keru_measurement=target/verus-measurement/libkeru_measurement.rlib \
    examples/verified_measurement.rs
cargo run --example verified_measurement
```

## Pixel unscaling by a reciprocal

For positive finite binary32 scale $s$ and a nonnegative finite binary32 edge $x$, the product $t=xs$ is exact in binary64. It has at most 48 significant bits. Let $q$ be $t$ rounded to the nearest integer with ties away from zero, and let $u=q/s$ be the exact unscaled value. For $q>0$, the reciprocal and the unscaled intermediate values are within the normal binary64 range. The original binary64 division differs from $u$ by at most $2^{-53}u$. The binary64 reciprocal followed by binary64 multiplication differs by at most $(2^{-52}+2^{-106})u$, which is less than $2^{-51}u$.

If $q=t$, then $u=x$. A nonzero binary32 value is at least $2^{-25}u$ away from any binary32 rounding midpoint. Otherwise the nonintegral product has $t<2^{47}$, so $q\leq 2^{47}$. Write $s=m2^k$ and a binary32 midpoint $h=p2^e$ using odd positive integers $m<2^{24}$ and $p<2^{25}$. This representation also covers the subnormal midpoints and the overflow threshold. Any finite binary32 value $x$ is at least $2^e$ away from $h$.

If $k+e\geq 0$, then $sh$ is an integer. Equality $q=sh$ would imply $|t-q|=s|x-h|\geq 1$, contradicting $|t-q|\leq 1/2$. The nonzero integer gap gives $|u-h|/u=|q-sh|/q\geq 2^{-47}$.

If $k+e<0$, write $sh=mp/D$, where $D=2^{-(k+e)}$ is even. Then $qD-mp$ is a nonzero integer. A midpoint that could lie between the two binary64 approximations must satisfy $h\geq u/2$, so $qD\leq 2mp<2^{50}$. Hence $|u-h|/u=|qD-mp|/(qD)>2^{-50}$.

In each case the two binary64 approximations stay on the same side of every binary32 midpoint and produce identical published words. Negating the edge preserves the argument. Zero results and infinities keep their signs under both unscaling operations, and NaNs remain NaNs. The arithmetic checker verifies how the kernels compute and use the reciprocal. [Arithmetic checker](pixel_rounding.py)

## Fusing the half-pixel bias

The nonzero finite product of a binary32 edge and scale has at most 48 significant bits and fits in the normal binary64 exponent range. Its binary64 multiplication is exact. A positive scale preserves the edge's sign, including signed zeros and infinities, so the FMA kernel takes the bias sign from the original edge. The binary64 FMA and the separate binary64 multiply and add round the same exact biased value. Both then truncate and unscale identically. NaNs remain NaNs. Fusing in binary32 can move a value across a half-pixel boundary. [Arithmetic checker](pixel_rounding.py)

## Packed power-of-two scales

For $s=2^k$ with $-126\leq k\leq 126$, the scale and its inverse are both exact normal binary32 values. A finite scaled edge retains at most 24 significant bits. If its magnitude is at least $2^{23}$, it is already integral and snapping returns the original edge, including when the binary32 multiply overflows. The binary32 comparison cannot misclassify a finite scaled edge near $2^{23}$ because scaling is exact there. Below the cutoff, the product is exact whenever it is normal. Smaller products may round to a subnormal or signed zero, and either value snaps to the same signed pixel zero. The rounded integer fits exactly in binary32. Its product with the exact binary32 reciprocal is exact in binary64, so a binary32 multiply publishes the same once-rounded value as the generic path. The original lane preserves infinities and NaN classification when the comparison fails. [Packed kernel](../src/pixel_grid/vector.rs)

## Scope of the equivalence result

The acyclic history theorem covers mixtures of full, numeric and structural frames. The cyclic replay history starts with a full solve and supports sequences of edits with changing region cuts over a common finite slot universe. Proofs derive boundary readiness for independent Free parents and fixed-size Width grids, and derive placement stability from marked primitive edits and stable sizing reads. Mixed-region replay composes multiple cuts once their modeled boundary values and read schedules meet the per-cut conditions. The remaining native obligation is to establish those conditions and the ordered reads, side writes and preparation for every region selected by the optimized solver. The checked solve compares sizing and the entire generated view at runtime. [Numeric frame](numeric_frame.rs) · [Cyclic replay history](replay_history.rs) · [Mixed regions](mixed_regions.rs) · [Scoped boundaries](planner_boundary.rs) · [Placement completeness](placement_complete.rs) · [Checked integration](../src/incremental/checked_view.rs)

The public adapter contract requires consistent links, reported content changes, and repeatable measurement bits for the same node and inputs. This requirement is necessary for reuse. A callback that returns its invocation count can measure a branch at one pixel in the initial solve. An unrelated edit leaves that branch at one pixel in the incremental solve, while a fresh solve from the same adapter state measures it at two pixels. Callbacks may still update private caches and logs. Visible geometry excludes diagnostic warnings, allocation history and unused backing storage. The floating-point checks cover their named kernels, including their documented treatment of NaN. [Adapter contract](../src/lib.rs) · [Evaluator and cache](view.rs)

## Panic-freedom scope

The production slot encoder, packed flag reads and writes, bounded queue charge, and saturated population addition have Verus `no_unwind` contracts. The wrap scanner's verification covers its arithmetic and unwrap checks over a finite, consistent sibling chain. Placement widens the evenly spaced gap count before adding one. The placement-batch proofs bound both fixed arrays and the dirty-mask shifts, including early and final flushes. The text tail splitter and padded-copy kernel verify the borrowed slice, destination indices and lane mask. [Slot and count operations](../src/cycle_rules.rs) · [Queue budget](../src/dependency_rules.rs) · [Wrap scanner](../src/wrap_lines.rs) · [Batch proofs](placement_batch.rs) · [Text tail](../src/layout_tree/text_windows.rs)

The packed grid preflight keeps the dense occupancy allocation within its byte budget. Large spanning grids use a sparse first-fit search that preserves row-major ordering and backfill. The capacity and search proofs cover their arithmetic and bounds. Allocation success remains a host resource requirement. [Capacity guard](../src/grid_state.rs) · [Sparse search](../src/grid_sparse.rs) · [First-fit proof](grid_sparse.rs)

Topology ticket exhaustion leaves an empty snapshot and selects untracked reconciliation without reusing any ticket. Snapshot capture and untracked reconciliation walk iteratively. The verifier checks that closing a captured branch writes exactly its end and resumes at a strictly earlier parent index. A native regression exercises both walks on a deep chain on a small-stack thread. [Snapshot capture](../src/topology.rs) · [Branch closure](../src/topology/state.rs)

The owned-tree API requires a `ChildId` for moves and removal, which makes those actions unavailable on the root. Stale and foreign handles, cyclic moves and unavailable rectangles return `TreeError`. The executable capacity and incarnation guards prove that accepted reservations leave room for the arena sentinel and that publishing a rectangle preserves the handle's incarnation. The checked ancestry scan returns an error when a move would create a cycle. The removal traversal proves its live-link preconditions and cannot unwind if its arena operations satisfy their contracts. [Owned tree API](../src/layout_tree/id.rs) · [Structural guards](../src/layout_tree/structural_guard.rs) · [Removal](../src/layout_tree/removal.rs)

Preparation, structural planning, tracked reconciliation and placement now suspend work on explicit stacks. The shared stack proof covers LIFO order, and its inline operations have `no_unwind` contracts for array indexing and length arithmetic. Dependency sizing switches to an explicit worklist once its native depth budget reaches zero. Retention declines a branch beyond a separate native depth budget and lets iterative preparation handle it. The 8,192-node chain that previously exhausted a 256 KiB stack now passes both full and structural incremental solves on that stack. [Work stack](../src/work_stack.rs) · [Sizing depth](../src/sizing_stack.rs) · [Placement transition](../src/placement_walk.rs) · [Deep-tree regression](../tests/owned_api.rs)

An unconditional public-API panic-freedom theorem is false. For example, a context destructor supplied by the caller can panic during removal. The owned tree finishes unlinking the subtree before running those destructors. A crate-wide theorem under nonpanicking host callbacks remains open. It would need to connect the verified kernels to the native solver state and account for the standard library, the slot arena and available resources. Verus's `no_unwind` contracts cover unwinding at the marked boundaries. [Destructor regression](../tests/owned_api.rs) · [Verus unwinding specification](https://verus-lang.github.io/verus/guide/reference-unwind-sig.html)

## Runtime cross-checks

The public adapter tests compare against fresh output storage through reparenting, ID reuse, signed zero, visibility, scale and viewport changes. They exercise stale grid placement with unchanged sizing, a retained nonzero cell under a width-derived grid, and a rebuilt subtree under an unchanged fractional parent. The native tests also replay edits through no-wrap Fill, Wrap, width-derived grid and Block cycles, coupled stack tails and retained host measurements. [Adapter tests](../tests/adapter.rs) · [Structural tests](../tests/structural.rs) · [Solver tests](../src/solve.rs)

The differential fuzz suites compare absolute rectangle bits, including the sign of zero. A separate mixed-region sequence combines changes to Stack, Wrap, Block and width Grid subtrees for 300 frames across three pixel-scale settings. [Edit tests](../tests/incremental_fuzz.rs)

The feature-dispatch guarantee applies to portable builds and relies on Rust's CPU and OS feature detector. Compiling the entire application with stronger global target features sets the minimum hardware for the whole binary. The rounding test runs every kernel available on the host against the scalar specification. An emulated x86-64 CPU without AVX2 or AVX-512 executed the SSE2 route. [Backend tests](../src/pixel_grid.rs)

The batch tests compare complete and leftover rectangles with individual kernel calls. The stack placement test includes disabled, freely placed and nested siblings and compares callback order and the bits of both absolute and local rectangles against the scalar rounding specification. [Adapter tests](../tests/adapter.rs)
